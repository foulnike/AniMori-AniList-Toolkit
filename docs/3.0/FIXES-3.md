# Правки 3.0, волна 3

Восемь замечаний по живой сборке после страницы студии (3.10).
Порядок пунктов — порядок замечаний, коммиты идут группами по файлам.

## 1. Ссылки на Шикимори у людей не открывались

Кнопка «Открыть на Shikimori» в окошке человека собирала адрес
с буквальными двойными фигурными скобками внутри: открыть такое
нельзя, а мост молча отбрасывал. По решению хозяина кнопка убрана
вовсе — ссылок на тайтл достаточно в хвосте описания, — а само поле
`shikiUrl` удалено из конвейера: мёртвое и битое одновременно.
Старые записи склада с этим полем читаются штатно: при разборе
переносятся только известные свойства.

## 2. «Средняя %» в герое

Это была средняя оценка каталога AniList (averageScore, шкала 0–100).
Рядом со своей оценкой читалась непонятным дублём. Убрана из пилюль
героя; на плитках поиска и страницы студии оценка каталога осталась.
Позже в герой вернулся тройной рейтинг площадок (макет Б).

## 3. Разметка BBcode в русских описаниях

Описание с Шикимори приходит с тегами вида [character=123]...[/character],
и путь тайтлов их не чистил (у людей чистка была). titles.ts теперь
снимает парные и одиночные теги прогоном до неподвижной точки, пустое
после чистки считается отсутствием. Склад бессрочный, поэтому префикс
ключа поднят: сначала до RU2_ (описания без разметки), затем до RU3_
(с оценками площадок).

## 4. Полка персонажей разъезжалась при малом составе

Общий трек полки — minmax(168px, 1fr): при горсти лиц колонки
растягивались на всю ширину, и три портрета висели друг от друга
далеко. У народной полки трек фиксированный 132px: лица жмутся влево.

## 5. Про кэш имён и названий

Кэш работает и бессрочен: память сеанса плюс IndexedDB (shikiCache),
протухания нет, чистится только руками из настроек. Что видно на деле:
после перезапуска приложения память пуста, и названия поднимаются
с диска по мере чтения — латиница показывается сначала и подменяется
по готовности. Имена, доставшиеся даром из поиска, живут только
в памяти сеанса и на склад не пишутся. У части людей карточка из
списка ролей без описания: оно добирается одним запросом при открытии
окошка.

## 6. «Описания ни один источник не дал» при живом английском

Пустая строка от русского источника — не null, и запасной английский
с AniList за ней не открывался. Теперь описание — первое непустое
из русского и английского, а сообщение показывается, только когда
пусты оба.

## 7. Карточку сэйю нельзя было открыть из карточки персонажа

Строки голосов были просто текстом. Теперь это кнопки: карточка сэйю
открывается в том же окне со стеком «Назад», Escape идёт на шаг назад,
а в корне закрывает окно. Обещано ещё в 3.9б, потерялось при
переписывании.

## 8. Блок студий переехал и обзавёлся литографиями

Полоса во всю ширину зияла на фуллскрине рядом с пустым местом:
чипы переехали в колонку записи. Литографии берутся списком
/api/studios у Шикимори раз в сеанс и лежат на складе бессрочно:
u AniList картинок студий нет. Сверка по имени и filtered_name,
промах — чип без картинки. Позже, макетом Б, студии переехали
в героя третьим рядом пилюль.

## Что проверить на сборке

1. `npm run typecheck` зелёный.
2. Окошко персонажа: строка голоса открывает карточку сэйю, «Назад»
   и Escape возвращают к персонажу; кнопки Shikimori нет, AniList есть.
3. Описание тайтла без тегов [character=...]; где русского нет —
   английский текст, а не сообщение о пустоте.
4. Полка из трёх персонажей прижата влево.
5. Чипы студий сидят в герое (макет Б), у известных студий — литография.
6. В герое нет пилюли прогресса; рейтинг — три площадки.
