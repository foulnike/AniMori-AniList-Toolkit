# Контекст 3.0

Курс: свой клиент вместо надстройки. Первая цель — Windows. Список,
избранное и статистика — свои, обмен с чужими сервисами файлом.

## Где стоим

Этап 2 закрыт целиком. Из третьего закрыты пункты с 3.1 по 3.5:
окно, каркас экранов, списки, карточка и поиск. Манга стала
подвкладкой списков, русское слово ищется через Шикимори.
Прогон 17 августа зелёный, поиск отвечает быстро.

Следующий шаг — 3.4а, переделка карточки по замыслу владельца;
без его правок идём в 3.6, настройки и свои ссылки.
План — в `PLAN.md` и `PLAN-2.md`, реестр решений — в четырёх частях.

## Помеха снята

AniList держал временные ограничения API с 15 по 16 августа: анонимный
запрос отвечал 403. Клиент пережил без правок, сейчас API отвечает.

## Чего не знаем

- Вес ответа `MediaListCollection` на большом списке не мерян,
  постраничного обхода в коде нет.
- Ответ сервера на негодную правку не видели.
- Сколько тайтлов остаётся без русского названия, не считали.
- Время записи снимка вместе с дублем в файл не меряли.
- Подъём из файла при пустом хранилище вживую не проверялся.
- Отдаёт ли AniList выгрузку списка в MAL-совместимом XML.
- Равен ли номер Шикимори номеру MAL всегда: поиск на этом стоит.

## Долг кода

- `files.rs`: временный файл остаётся, если переименование не удалось.
- Дубль снимка пишется на каждое сохранение, а не по двум точкам.
- Кнопка «Назад» рисуется дважды: в карточке и в рамке оболочки.
- Тома манги очередь правок отправить не умеет.
