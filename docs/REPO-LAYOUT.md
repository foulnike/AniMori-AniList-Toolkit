# Карта репозитория: ветка скрипта

> [!NOTE]
> Этот файл лежит в ветке `script` и говорит только за неё. У ветки приложения есть свой такой же файл со своим содержанием. Не сливайте их.

Один репозиторий, три ветки, три разных продукта. Общей кодовой базы между скриптом и приложением больше нет: до версии 1.9 юзерскрипт и настольная оболочка собирались из одних и тех же исходников, 24.08.2026 их разделили окончательно.

## Ветки

| Ветка | Продукт | Состояние |
| --- | --- | --- |
| `script` | Юзерскрипт для AniList | Живая, работа идёт здесь |
| `app-3.0-dev` | Настольное приложение 3.0 (Tauri + Vue) | Живая, отдельная кодовая база |
| `main` | Гибрид 2.x, каким он был на последнем выпуске | Заморожена, хранит `dictionary.json` |

Переразметку `main` отложили до того, как приложению будет что показать. До тех пор в `main` ничего не правим.

## Что лежит здесь

```
src/main.ts            порядок запуска: один шаг — одна возможность
src/core/              настройки, БД, словарь, жизненный цикл, сеть
src/api/              AniList, Шикимори, anime365, AnimeThemes, словарь
src/features/         возможности: интерфейс, переводчик, поиск,
                      медиа-виджеты, сканер, перенос списка
src/bridge/           доступ к GM_*-функциям через один слой
src/utils/            DOM, журнал, сверка названий, монтирование Vue
src/style.scss        все стили скрипта одним файлом
dictionary.json       рабочая копия словаря (боевая — в main)
```

Сборка даёт два файла: `dist/animori.user.js` (сам скрипт, около 630 КБ) и `dist/animori.meta.js` (только шапка, для проверки обновлений).

## Чего здесь нет и быть не должно

| Чего нет | Где это |
| --- | --- |
| `src-tauri/`, Rust, оболочка окна | Ветка `app-3.0-dev` |
| `TauriBridge`, вызовы `@tauri-apps/*` | Ветка `app-3.0-dev` |
| Блокировщик рекламы | Нигде: в браузере рекламу режет расширение пользователя |
| Прокси-туннель и его настройки | Ветка `app-3.0-dev` |
| Скриншоты и архив документации 2.x | Ветка `main` и уже вышедшие релизы |

Проверок вида `Bridge.platform !== 'tauri'` в коде больше нет: платформа здесь одна, и тип `platform` сузился до `'userscript'`. Если такая ветвь появилась снова — вместе с ней сюда приехал чужой код.

## Выпуски

| Тег | Что собирает | Куда попадает |
| --- | --- | --- |
| `script-*` | Юзерскрипт из этой ветки | Релиз на GitHub с `animori.user.js` |
| `app-*` | Приложение из ветки `app-3.0-dev` | Релиз с установщиком и `latest.json` |
| `v*` | Ничего, это история гибрида 2.x | Старые релизы, не переиспользуем |

Порядок выпуска здесь: поднять `version` в `package.json`, переименовать блок `## [Не выпущено]` в `CHANGELOG.md`, поставить тег `script-<версия>`. Сборочный поток лежит в `.github/workflows/release.yml` и срабатывает только на `script-*`.

На Greasy Fork файл выкладывается руками — [скрипт 572948](https://greasyfork.org/ru/scripts/572948-animori-anilist-toolkit). Автообновления из релиза GitHub у нас нет, поэтому пропущенная выкладка означает, что пользователи остались на прежней версии.

## Куда не сливать

- `script` → `app-3.0-dev` и обратно: ветки разошлись намеренно, слияние вернёт удалённое.
- Что угодно → `main`: ветка заморожена.
- Общие правки (лицензия, шаблоны обращений) вносим в каждую ветку отдельным коммитом.

Черри-пик между `script` и `app-3.0-dev` возможен только для файлов, которых разделение не касалось. На практике это `LICENSE` и содержимое `.github/`.

## Словарь

`dictionary.json` (около 185 КБ) лежит и в `main`, и здесь. Скрипт качает его по адресу из `DICT_URL` — а он смотрит на `main`:

```
https://raw.githubusercontent.com/foulnike/AniMori-AniList-Toolkit/main/dictionary.json
```

Значит, правка словаря в этой ветке пользователей не достигнет, пока та же правка не попадёт в `main`. Двойное хранение — временная неловкость; куда словарь переедет насовсем, решим при переразметке `main`. Пополняют его через шаблоны обращений `dictionary-bulk.yml` и `translation.yml` с метой `dictionary`.

## Две ветки на одной машине

У скрипта и приложения разные наборы зависимостей: здесь есть `@types/greasemonkey` и `vite-plugin-monkey`, там — `@tauri-apps/*`. После `git switch` между ветками `node_modules` оказывается не тот, и проверка типов падает с `TS2688: Cannot find type definition file for 'greasemonkey'`. Лечится `npm install`, но проще не переключаться вовсе:

```bash
git worktree add ../animori-script script
cd ../animori-script
npm install
```

Теперь ветка приложения живёт в основном каталоге, скрипт — в соседнем, и `node_modules` у каждого свой. Убрать второе дерево: `git worktree remove ../animori-script`.
