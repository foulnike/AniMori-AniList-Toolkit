# Устройство репозитория

До версии 3.0 репозиторий был одной кодовой базой на два продукта. Теперь
продукты разъехались по веткам. Этот файл — карта того, что где лежит.

## Ветки

| Ветка | Что в ней | Тег выпуска |
| :--- | :--- | :--- |
| `app-3.0-dev` | настольное приложение со своим интерфейсом (Vue + Tauri) | `app-<версия>` |
| `script` | пользовательский скрипт для Tampermonkey | `script-<версия>` |
| `main` | история монолита 2.x и словарь перевода | `v2.0.2` и раньше |

Ветки самостоятельны: вливать одну в другую не нужно и нельзя — у них разные
сборка, зависимости и конвейеры выпуска.

### Почему main заморожен

В `main` лежит последний монолит 2.0.2 целиком. По нему восстанавливается
любой состоявшийся релиз, поэтому ветка не переписывается.

Одно правило обязательно: **`dictionary.json` остаётся в `main` навсегда**.
Словарь перевода каждый клиент тянет по прямому адресу
`raw.githubusercontent.com/.../main/dictionary.json`. Перенесёшь или удалишь —
перевод отвалится сразу у всех установленных копий всех версий.

В `main` же живёт еженочной конвейер `watch-dataset`, собирающий датасет
названий. Подробности — в `DATASET-MAINTENANCE.md`.

## Что было уничтожено

Старая реализация десктопа — окно с самим сайтом anilist.co, в которое сборка
вшивала тот же юзерскрипт. Из рабочих веток убраны все её части: `hybrid.rs`,
`adblock.rs` со `src/shared/adblock/`, `proxy_guard.rs`, `capabilities/site.json`
и команда `animori_open_site`.

В этапе 3 туда же ушла отправка правок на сервер: `core/edit-queue.ts`
и `core/edit-sender.ts`. Список теперь односторонний — см. `STORAGE-AND-SYNC.md`.

Состоявшиеся релизы и теги 2.x не тронуты: артефакты скачиваются, а
установленные копии продолжают работать.

### Как старые копии переедут на 3.0

Сами. У нового приложения тот же `identifier` (`com.foulnike.animori`), тот же ключ
подписи и тот же адрес манифеста обновлений. Первый же релиз `app-3.0.0`
сдвигает `releases/latest`, и апдейтер старой оболочки видит 3.0.0 > 2.0.2.
Настройки и токен лежат в том же профиле и подхватываются.

## Сборка

```bash
npm install
npm run dev:app      # передний край в браузере
npm run tauri:dev    # окно приложения
npm run tauri:build  # установщик
npm test             # проверки ядра
```

Режимов сборки больше нет: `vite.config.ts` один и безусловный.
`npm run build:app` сначала гоняет `typecheck:all`, потом собирает передний
край в `dist/app`. Его зовёт и `beforeBuildCommand`, и `beforeDevCommand`, поэтому
`tauri:dev` каждый раз пересобирает разметку целиком: сервера разработки
с горячей подстановкой в окне нет.

### Граница ядра

- `src/shared/` — ядро. Про свою оболочку не знает ничего.
- `src/app/` — надстройка: экраны, компоненты, роутер.
- `src-tauri/` — оболочка на Rust.

`npm run typecheck:shared` проверяет ядро в отдельности: в этой проверке
каталога `src/app` не существует, и любая стрелка из ядра в надстройку
ломает сборку. Граница важна и после разделения: ядро живёт сразу в двух
ветках, и перенос правки между ними дешёв только пока это так.

Правило трёх файлов: новый алиас ядра прописывается в `vite.config.ts`,
`tsconfig.json` и `tsconfig.shared.json`. Пропустить один — получить расхождение
между сборкой и проверкой типов.

## Перенос правки ядра в ветку script

В `script` ядро лежит в `src/`, а здесь — в `src/shared/`, поэтому `git cherry-pick`
между ветками напрямую не работает:

```bash
git format-patch -1 <коммит> --stdout > /tmp/fix.patch
git checkout script
git apply --directory=. -p3 /tmp/fix.patch   # подобрать -p под сдвиг путей
```

Правки в ядре стоит делать отдельными коммитами, не смешивая с правками
интерфейса.

Облачная часть и выгрузка в XML в юзерскрипт не переносятся: они опираются
на мост и файловую систему, которых в браузере нет.

## Выпуски

- `app-<версия>` → `windows-latest`, компиляция Rust, установщик, подпись,
  `latest.json`, портабл-архив.
- `script-<версия>` → `ubuntu-latest`, только Node, два файла в релиз.

Оба конвейера берут описание релиза из верхнего раздела `CHANGELOG.md` своей
ветки и падают, если номер в теге расходится с `package.json`.

## Мелкие следствия разделения

Файл разрешений теперь один — `src-tauri/capabilities/default.json`. Вместе с окном
сайта ушёл `site.json`, но разрешение `allow-animori-reload` жило только в нём —
его пришлось выдать главному окну явно.

Счётчик неудачных попыток прокси больше не сбрасывается сам: сброс делал страж,
который следил за загрузкой страницы сайта. После пяти неудач подряд
помогает перезапуск приложения.
