# Устройство репозитория

До версии 3.0 репозиторий был устроен как одна кодовая база на два продукта.
Теперь продукты разъехались по веткам. Этот файл — карта того, что где лежит
и почему.

## Три ветки

| Ветка | Что в ней | Теги выпусков |
| :--- | :--- | :--- |
| `app-3.0-dev` | настольное приложение со своим интерфейсом (Vue + Tauri) | `app-3.0.0` |
| `script` | пользовательский скрипт для Tampermonkey | `script-2.1.0` |
| `main` | история монолита 2.x и словарь перевода | `v2.0.2` и раньше |

Ветки самостоятельны: вливать одну в другую не нужно и нельзя — у них разные
сборка, разные зависимости и разные конвейеры выпуска.

### Почему main заморожен, а не переписан

В `main` лежит последний монолит 2.0.2 целиком, включая код старой гибридной
оболочки. Его не трогали намеренно: по этим файлам восстанавливается любой
состоявшийся релиз, и на них же ссылаются старые обсуждения и история
решений. Реструктуризация `main` — отдельная задача на потом.

Одно исключение обязательно: **`dictionary.json` должен остаться в `main` навсегда**.
Словарь перевода каждый клиент тянет по прямому адресу
`raw.githubusercontent.com/.../main/dictionary.json`. Перенесёшь или удалишь файл —
перевод отвалится сразу у всех установленных копий всех версий.

## Что было уничтожено

Старая реализация десктопа — окно с самим сайтом anilist.co, в которое сборка
вшивала тот же юзерскрипт. Из рабочих веток убраны все её части:

- `src-tauri/src/hybrid.rs` — встраивание скрипта и стилей в чужую страницу;
- `src-tauri/src/adblock.rs` и `src/shared/adblock/` — блокировщик рекламы, который
  имел смысл только внутри такого окна;
- `src-tauri/src/proxy_guard.rs` — страж, следивший, что страница сайта вообще
  открылась через прокси;
- `src-tauri/capabilities/site.json` — права окна с чужим сайтом;
- команда `animori_open_site` и вся обвязка вокруг неё.

Состоявшиеся релизы и теги 2.x не тронуты: артефакты скачиваются, а
установленные копии продолжают работать.

### Как старые копии переедут на 3.0

Сами. У нового приложения тот же `identifier` (`com.foulnike.animori`), тот же ключ
подписи и тот же адрес манифеста обновлений — `releases/latest/download/latest.json`.
Первый же релиз `app-3.0.0` сдвигает `releases/latest`, и апдейтер внутри
старой оболочки видит версию 3.0.0 > 2.0.2 и предлагает обновиться.
Отдельного переезда делать не надо; настройки и токен лежат в том же профиле
(`AppData\Roaming\com.foulnike.animori`) и подхватываются новой версией.

## Как собирается приложение (эта ветка)

```bash
npm install
npm run dev:app      # передний край в браузере
npm run tauri:dev    # окно приложения
npm run tauri:build  # установщик
```

Режимов сборки больше нет. Прежде `vite.config.ts` разветвлялся на три пути
(`userscript`, `app`, `tauri`) и собирал разные продукты из общих файлов;
теперь конфиг один и безусловный. `npm run build:app` собирает только
передний край в `dist/app` — его же зовёт Tauri через `beforeBuildCommand`.

### Граница ядра

- `src/shared/` — ядро: API, данные, кэш, мост. Про свою оболочку не знает ничего.
- `src/app/` — надстройка: экраны, компоненты, роутер.
- `src-tauri/` — оболочка на Rust.

`npm run typecheck:shared` проверяет ядро в отдельности: в этой проверке каталога
`src/app` не существует, и любая стрелка из ядра в надстройку ломает сборку.
Граница остаётся важной и после разделения: ядро живёт сразу в двух ветках,
и перенос правки между ними остаётся дешёвым только пока это так.

Правило трёх файлов: новый алиас ядра прописывается в `vite.config.ts`,
`tsconfig.json` и `tsconfig.shared.json`. Пропустить один — получить расхождение
между сборкой и проверкой типов.

## Перенос правки ядра в другую ветку

Сложность в том, что в ветке `script` ядро лежит в `src/`, а здесь —
в `src/shared/`. Поэтому `git cherry-pick` между ветками не работает напрямую.
Надёжный способ:

```bash
git format-patch -1 <коммит> --stdout > /tmp/fix.patch
git checkout script
git apply --directory=. -p3 /tmp/fix.patch   # подобрать -p под сдвиг путей
```

Правки в ядре стоит делать отдельными коммитами, не смешивая их с правками
интерфейса — иначе переносить придётся вручную.

## Выпуски

Каждый продукт выпускается своим тегом и своим конвейером в своей ветке:

- `app-<версия>` → `windows-latest`, компиляция Rust, установщик, подпись,
  `latest.json`, портабл-архив. Номер сверяется с `package.json`.
- `script-<версия>` → `ubuntu-latest`, только Node, два файла в релиз.

Оба конвейера берут описание релиза из верхнего раздела `CHANGELOG.md` своей
ветки и падают, если номер в теге расходится с `package.json`.

## Мелкие следствия разделения

Файл разрешений теперь один — `src-tauri/capabilities/default.json`. Вместе с окном
сайта ушёл и `site.json`, но разрешение `allow-animori-reload` жило только в нём —
его пришлось выдать главному окну явно.

Счётчик неудачных попыток прокси больше не сбрасывается сам: сброс делал страж,
который следил за загрузкой страницы сайта. После пяти неудач подряд
помогает перезапуск приложения. Если станет мешать — сбрасывать счётчик
по успешному запросу к AniList.
