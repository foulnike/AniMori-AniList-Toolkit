## Команда `animori_anilist_query` (`src-tauri/src/anilist.rs`)

Единственный путь запросов GraphQL в десктопе. Разметка отдаёт только
тело запроса и признак `useAuth`; адрес `https://graphql.anilist.co` и пропуск
живут только в Rust, чтобы токен не покидал оболочку.

Пропуск берётся из `animori-settings.json` по ключу `auth_token`. Если подпись
просят, а токена нет, команда сразу возвращает ошибку и в сеть не ходит.
Настройки прокси читаются из того же файла (`set_proxy_on`, `set_proxy_kind`,
`set_proxy_host`, `set_proxy_port`, `set_proxy_login`, `set_proxy_pass`), порт `0`
означает «значения нет».

Ответ — `AniListReply` в `camelCase`: код, заголовки и сырой текст. Код и заголовки
нужны клиенту для ограничителя темпа и `Retry-After`, поэтому тело не разбирается
в Rust. Имена заголовков приводятся к нижнему регистру: сервис меняет регистр,
а клиент ищет ключ одним написанием.

Ошибки размечаются префиксами `timeout:` и `network:` — так `TauriAniList.ts`
собирает `BridgeHttpError` с верным видом, не разбирая человеческие тексты.
Таймаут — 30 секунд. Клиент `reqwest` собирается на каждый запрос: настройки
прокси меняются без перезапуска, и долгоживущий клиент держал бы старые.
Свой `user_agent()` собирается из версии пакета: AniList требует узнаваемого
клиента и без него отвечает 403 через Cloudflare.

В перечне команд `lib.rs` она стоит рядом с сетевыми обработчиками
и регистрируется одним списком с остальными.

### Разрешение

`capabilities/default.json` даёт `allow-animori-anilist-query` только окну `main`.
Окна `site` и `login` его не имеют намеренно: страница сайта и экран входа
не должны дотянуться до подписанных запросов. Новое окно с запросами
к AniList придётся вносить в разрешение явно.

## Подсистема файлов моста

Контракт `IFiles`: `available`, `read`, `write` с булевым исходом. Ядру нужен
ответ «есть ли диск» без проверки платформы. Наружу идёт имя, а не путь:
каталог выбирает оболочка, и общий код не может попросить себе чужое место.

В десктопе — команды `animori_file_read` и `animori_file_write`; ни чтение,
ни запись не отклоняются, отказ уходит в консоль. В браузере честная заглушка:
`available: false`, `null` и `false` молча. Скачивание файла заменой не служит:
оно требует жеста пользователя и не читается обратно.

`src-tauri/src/files.rs`: имена только из белого списка (`animori-snapshot.json`
и забронированное `animori-queue.json`), каталог — приватный каталог приложения,
он же создаётся при первом обращении. Запись идёт во временный файл
с переименованием: гибель процесса посередине оставила бы обрезок вместо
снимка. Потолок записи — восемь мегабайт. Отсутствие файла ошибкой не считается
и возвращается как «нет данных».

Очередь правок в файл пока не дублируется: имя забронировано впрок.

Долг: при упавшем переименовании временный файл остаётся на диске.

### Разрешения файловых команд

Обе команды выданы только окну `main` в `capabilities/default.json`: чужому
сайту нечего читать и переписывать в нашем снимке. Места регистрации те же три,
что у любой команды, — `invoke_handler` в `lib.rs`, `COMMANDS` в `build.rs`,
разрешение в capability нужного окна; для вызова из разметки добавляются
контракт моста и обе его реализации.
