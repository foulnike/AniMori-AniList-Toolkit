# Документация AniMori

Семь документов, и каждый отвечает на свой вопрос.

| Документ              | Вопрос                              |
| --------------------- | ----------------------------------- |
| `ARCHITECTURE.md`     | Как это устроено                    |
| `DECISIONS.md`        | Почему устроено именно так          |
| `DATA-PIPELINE.md`    | Откуда берутся русские названия     |
| `STORAGE-AND-SYNC.md` | Где живут списки пользователя       |
| `CONVENTIONS.md`      | Как писать код и документацию       |
| `ROADMAP.md`          | Что дальше                          |
| `archive/`            | Как было раньше                     |

Правила ведения — в `CONVENTIONS.md`, раздел «Документация». Коротко:
документ описывает настоящее, устаревшее удаляется, история живёт в git.

---

## История этой папки

До 20 августа 2026 года документация состояла из двадцати четырёх файлов:
семь частей карты проекта, шесть файлов решений с номерами, три файла
исправлений, два плана и отдельные правила. Велась она дисциплинированно,
но устроена была как журнал: новое дописывалось, старое оставалось
с пометкой «отменено».

Отсюда выросли все её беды. Файл упирался в потолок размера и делился
на `-2`, `-3`, `-4`. Истина размазывалась по шести файлам с датами,
и чтобы узнать текущее положение дел, приходилось читать их все
в правильном порядке. Проверка кодом 20 августа нашла три расхождения
с действительностью: карта экранов описывала главную, которой не стало
суткой раньше; префикс кэша русских имён разошёлся в трёх документах;
раздел про адреса обещал пять и перечислял шесть.

Оборонительный тон оттуда же. Когда документ нельзя переписать,
единственный способ защититься от неверного прочтения — обвешать запись
предупреждениями. Отсюда взялись «РИСК №3», пометки о статусе на дату
и потолки в три строки на комментарий.

Старые файлы удалены целиком. Всё верное из них перенесено сюда, всё
краткосрочное осталось в `git log`.
