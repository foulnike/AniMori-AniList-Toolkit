# Архитектура

Один исходник, два продукта. Юзерскрипт-надстройка над сайтом anilist.co
и десктопное приложение на Tauri. Общее ядро лежит в `src/shared/`,
продуктовые части — в `src/userscript/` и `src/app/`.

AniList не переведён на русский и недоступен из России без прокси.
AniMori склеивает несколько источников в один интерфейс: каталог и списки
берутся у AniList, русские названия и описания — у anime365 и Шикимори,
персонажи и авторы — у Шикимори, видео — у Kodik, музыка — у AnimeThemes.

## Мост

`src/shared/bridge/` прячет разницу платформ за одним контрактом. Ядро
никогда не спрашивает, где оно работает.

| Группа      | Браузер                       | Десктоп                                     |
| ----------- | ----------------------------- | ------------------------------------------- |
| `storage`   | `GM_getValue` / `GM_setValue` | плагин store, файл `animori-settings.json`  |
| `http`      | `GM_xmlhttpRequest`           | плагин http, запрос идёт из Rust, без CORS  |
| `anilist`   | через свой `http`             | команда `animori_anilist_query`             |
| `clipboard` | `GM_setClipboard`             | плагин clipboard-manager                    |
| `shell`     | `location.reload()`           | команды перезагрузки и полного экрана       |
| `files`     | честная заглушка              | `animori_file_read` / `animori_file_write`  |

Поле `platform` есть, но ветвить по нему логику не стоит: разница платформ
уходит в реализацию моста или в алиас сборки. Оно нужно для диагностики
и текстов.

Подсистема `anilist` отделена от `http` не для красоты. В десктопе адрес
и пропуск живут только в Rust, а наверх идёт лишь тело запроса и просьба
его подписать. Токен не покидает оболочку вовсе. Реализация вынесена
в отдельный `TauriAniList.ts`, потому что `TauriBridge.ts` стоял у потолка
размера.

Подсистема `files` отдаёт наружу имя, а не путь. Каталог выбирает оболочка,
и общий код не может попросить себе чужое место. Имена берутся из белого
списка: `animori-snapshot.json` и забронированное впрок `animori-queue.json`.
Запись идёт во временный файл с переименованием — гибель процесса посередине
оставила бы обрезок вместо снимка.

## Слой запросов

### Ограничитель темпа

`api/rate-limit.ts` заводит ограничитель на источник, а не на домен: лимит
считается по IP, и зеркала делят один бюджет.

| Источник                                 | Интервал | Потолок за минуту          |
| ---------------------------------------- | -------- | -------------------------- |
| Шикимори, anime365, AnimeThemes          | 300 мс   | 60                         |
| AniList                                  | 100 мс   | старт 30, предохранитель 90 |

`acquireSlot()` — единственный вход. Слоты выдаются по одному через шлюз:
без него два параллельных вызова занимают один слот. Ждать приходится
по трём причинам сразу — не вышел интервал, стоит пауза, окно выбрано
до потолка.

Плавающий потолок включён только у AniList: остальные источники заголовков
не присылают. Снижение принимается всегда, рост — только когда кончилось
восстановление. Ответ 429 режет потолок вдвое и закрывает рост на пять минут.
Ниже шести запросов в минуту потолок не опускается: серия 429 иначе
остановила бы работу вовсе.

Заявленные лимиты сервисов и фактические расходятся. У AniList заявлено
около 90 запросов в минуту, на деле часто 30. Наши числа взяты с запасом.

### AniList

`api/anilist.ts` — единственная точка GraphQL и держатель общей паузы:
только клиент видит все запросы к AniList сразу.

Заголовки читаются из любого ответа, включая ошибки, и в любом регистре
имени: мост в Rust имена понижает, скриптовый отдаёт как пришло.
`x-ratelimit-limit` учит потолок, нулевой `x-ratelimit-remaining` ставит
паузу до `x-ratelimit-reset`, но не длиннее минуты.

Ответ 429: пауза по `retry-after` либо пять секунд, потолок урезается,
повтор до трёх раз. Отказ сервера — это 403, 408 и всё от 500: пауза
30 секунд с удвоением до пятнадцати минут, любой удачный ответ обнуляет
серию. Паузу дольше десяти секунд вызов не высиживает, а бросает ошибку
с остатком: обещание, висящее пятнадцать минут, выглядит зависанием.

**403 неоднозначен.** Именно его отдаёт AniList и когда закрывает доступ
к API насовсем, и когда сервис лёг. С 15 по 17 августа 2026 года владелец
ввёл временные ограничения из-за выросшей нагрузки, и любой запрос с любым
клиентом получал 403. Наша сторона вела себя верно: отступ рос
до пятнадцати минут, правки лежали в очереди, список показывался из снимка.
Различить два случая по одному коду нельзя, и в журнале при отказе
не хватает начала тела ответа и заголовков `cf-ray`, `retry-after`,
`x-ratelimit-*`.

### Русские названия

`api/titles.ts` — выборщик источника. Порядок задан настройками:
`titlePrimary` по умолчанию **anime365**, `titleFallback` — **Шикимори**.
При пустом ответе основного спрашивается запасной.

Это важно и часто понимается наоборот. Шикимори не главный источник
названий, он запасной. Обоснование в коде: у anime365 нет манги вовсе
и части русских названий. После снятия манги первая половина этого
обоснования отпадает, и порядок источников стоит пересмотреть заново.

`resolveTitle(malId, type)` отдаёт **одним запросом** название, описание,
ссылку, имя источника, оценку MAL и распределение голосов Шикимори.
Отсюда растёт главная проблема производительности: тот же самый запрос
обслуживает и сетку списка, где описание не нужно, и открытую карточку,
где нужно всё. Разделение этих двух путей — предпосылка перехода
на датасет, см. `DATA-PIPELINE.md`.

BBcode из описаний вычищается здесь же, на входе.

### Остальные источники

- `shikimori.ts` — `fetchShiki` с перебором зеркал (`shikimori.io`,
  `shikimori.rip`). Возвращает и сработавший домен: ссылки строятся
  от того же зеркала, с которого пришли данные.
- `shikimori-people.ts` — самый капризный источник. Имена ищутся
  по схожести строк; при низкой уверенности кандидат проверяется
  по общим тайтлам, иначе вместо одного Сато встаёт другой.
- `anime365.ts` — русские названия и описания, только аниме. Счётчик
  ошибок гасит источник до конца сессии.
- `anilist-list.ts`, `anilist-edit.ts`, `anilist-media.ts`,
  `anilist-lookup.ts`, `anilist-catalog.ts`, `anilist-people.ts`,
  `anilist-person.ts` — списки, правки, карточка, выписки пачками,
  полки главной и люди тайтла.
- `animethemes.ts` — открывающие и закрывающие темы для виджета музыки.
- `dictionary.ts` в `userscript/` — словарь интерфейса с GitHub: сначала
  кэш, сеть фоном, чтобы перевод не ждал сети.

## Хранение

Три места, и различает их цена потери.

| Что                            | Где                      | Если потеряется   |
| ------------------------------ | ------------------------ | ----------------- |
| Ответы сети, русские карточки  | IndexedDB                | добудется заново  |
| Снимок списка и очередь правок | хранилище моста          | правки взять негде |
| Второй экземпляр снимка        | файл приватного каталога | остаётся главный  |

### IndexedDB

База `AniMoriSuperDB`, версия 5, три стора: `shikiCache` по строковому
ключу, `malCache` и `franchiseCache` по числовому.

Префиксы ключей в `shikiCache`:

| Префикс     | Что лежит                              |
| ----------- | -------------------------------------- |
| `RU3_`      | русская карточка: имя, описание, оценки |
| `LOOK2_`    | облик тайтла: обложка, цвет, части     |
| `MED2_`, `FULL_` | карточки Шикимори                 |
| `CHR2_`     | персонажи                              |
| `STF3_`     | авторы                                 |
| `THEMES2_`  | музыкальные темы                       |
| `RATE1_`    | оценки площадок                        |

Цифра в префиксе — версия формы записи. Меняется форма — растёт цифра,
и старые записи просто перестают находиться. Это дешевле миграции.

Имя `shikiCache` — долг: к Шикимори половина его содержимого отношения
не имеет.

Срока годности у записей нет: `CACHE_TIME` бесконечен, сборщик мусора
запускается и выходит сразу. Единственная чистка — кнопка в настройках.

Открытие базы разрешается всегда и ровно один раз: соединением, `null`
по ошибке или `null` по таймауту в семь секунд. Работа без кэша медленна,
но это работа; висящий старт — мёртвое приложение. Соединение снимает
само себя при `versionchange` и `close`, иначе в памяти остался бы битый
экземпляр до конца сеанса.

### Снимок и очередь

Подробно — в `STORAGE-AND-SYNC.md`. Коротко: две записи в хранилище моста,
`AM_SNAPSHOT` и `AM_EDIT_QUEUE`, плюс второй экземпляр снимка в файле.

## Слой данных

Порядок пуска держит `app/main.ts`: сначала `loadSettings()`, затем
`initCollection()` — подъём снимка и накат очереди, — затем
`startEditSender()`.

Порядок не случаен ни в одном звене. Настройки первыми: иначе первая
перерисовка идёт на значения по умолчанию, и тумблеры показа не работают
всю жизнь окна. Отправщик последним, но обязательно: без его запуска
фоновый разбор очереди и повтор при возврате сети мертвы.

Обновления со сервера на старте нет. Перенос списка идёт только по прямому
действию человека и замещает местный список целиком.

```
экраны
  ├─ collection-view.ts  отборы и счётчики (только чтение)
  ├─ adult.ts            единый отбор 18+
  ├─ edit-sender.ts      queueEdit → collection.ts → snapshot.ts
  ├─ media-title.ts      русские карточки → db.ts, api/titles.ts
  ├─ media-looks.ts      обложка, цвет, части → db.ts
  └─ media-search.ts     поиск по своему списку и по чужому каталогу
collection.ts  ← api/anilist-list.ts
edit-sender.ts → api/anilist-edit.ts
```

### collection.ts

Записи держатся словарём по номеру тайтла: карточка и каждая правка ищут
запись по номеру, а обход тысяч записей на приставке виден глазом.

Ответ сервера — основа, неотправленные правки накатываются сверху, иначе
оценка откатилась бы на глазах. Обновление замещает спрошенные типы
целиком: сервис источник истины, а удалённое там не должно жить в памяти
навечно. Идёт оно только по прямому действию человека: автоматический
заход при открытии экрана стирал бы правки втихую.

Правка неизвестного тайтла создаёт пустую запись — так выглядит
добавление, которого сервер ещё не видел.

Долг: понятия «подключённый сервис» в ядре нет, есть только номер хозяина
AniList.

### media-title.ts

Путь чтения трёхуровневый: память запуска, склад, сеть.

В памяти запоминается и отсутствие перевода. Без этого каждая перерисовка
била бы в сеть за тем же отказом. Сетевой сбой не запоминается: сеть
вернётся — спросим снова.

Пачка добывается по очереди, а не веером: сотня одновременных запросов
сразу упирается в темп. Соответствия MAL при этом берутся одним запросом
на всю пачку.

Отдельно держатся русские имена, доставшиеся даром вместе с чужим ответом
(например, из поиска по Шикимори). Они лежат в своей карте: описания
и ссылки там нет, и выдавать голое имя за полную карточку нельзя.

### edit-sender.ts

Единственный путь изменений на сервер. `queueEdit()` меняет память, пишет
очередь и толкает разбор. Без входа очередь не набивается вовсе — правка
живёт местно.

Разбор идёт строго по порядку и в одном потоке: две правки одного тайтла
местами менять нельзя. Пустая строка в правке дат и комментария значит
«стереть».

Правка выбрасывается двумя путями, и оба намеренные:

1. **Отказ по содержанию** — сервер её не примет никогда. Выбрасывается
   сразу, иначе одна плохая запись заперла бы очередь навсегда.
2. **Пять попыток** — попытка засчитывается только при ответе сервера,
   пауза по темпу её не тратит. Вечная правка стопорит всю очередь позади
   себя, а порядок нарушать нельзя.

Оба случая идут в журнал. Долг: в хранилище нет разницы между «доставлено»
и «сдались» — обе ветки помечают правку принятой.

Заходы: раз в минуту и на событие `online`. Пока стоит общая пауза AniList,
разбор не начинается. Сейчас файл знает только AniList.

## Оболочка Tauri

### Окна двух родов

Окно `main` грузит свою сборку из `dist/app` — это локальный фронтенд.
Окно `site` — браузер одного сайта: живой anilist.co со встроенной
надстройкой, запасной вид на время неполных своих экранов. Окно `login`
держит форму входа.

Отсюда три следствия:

1. оба окна создаются кодом, а не в `app.windows` конфига: окну с сайтом
   нужны внешний адрес и скрипты инициализации;
2. разрешения разведены: `capabilities/default.json` для своего окна,
   `capabilities/site.json` для окна с чужим доменом;
3. внешние ссылки перехватываются в `on_navigation` и уходят в системный
   браузер: иначе окно уехало бы на сторонний сайт без адресной строки.

Бандл и стили надстройки вшиваются в двоичный файл через `include_str!`
из `dist/`. Поэтому `npm run build:tauri` обязателен до `cargo`: без бандла
сборка Rust падает на чтении файла.

### Вход

Вход AniList идёт без системного браузера: форма открывается в окне
с меткой `login`, которое идёт через наш прокси. Сайт недоступен из РФ,
а нашего прокси внешний браузер не знает.

Пропуск возвращается на `http://127.0.0.1:48513/relay`. Приёмник слушает
только петлю, сам отдаёт страничку-стрелочник и гаснет через пять минут.
Разметка видит только факт входа и срок, сам пропуск в неё не попадает.
Ручная вставка — запасной путь, если возврат не дойдёт.

Окна создаются только из рабочего потока, поэтому все команды открытия
асинхронные: в главном потоке `build()` ждёт сам себя.

### Прокси

Трафик десктопа идёт двумя независимыми каналами, и прокси настраивается
для каждого своим способом: страница — через ключи запуска WebView2,
запросы из Rust — через опцию клиента. Ключи WebView2 читаются один раз
при создании первого окна, поэтому решение о прокси принимается до него,
а смена настройки требует перезапуска.

`proxy.rs` сводит всё к одному из четырёх исходов: выключено, неверные
данные, адрес не отвечает, применено. Исход отдаётся интерфейсу командой:
молчаливое применение нерабочего прокси выглядит как поломка приложения.

`proxy_auth.rs` подставляет логин с паролем на событие базовой авторизации
WebView2, только под Windows: ключом запуска их не передать, а без
обработчика запрос отменяется молча. Событие одно и на 407 от прокси,
и на 401 от сайта, поэтому адреса из списка исключений пропускаются,
а число попыток подряд ограничено: кода ошибки в событии нет, и повтор
считается признаком неверного пароля.

`proxy_guard.rs` страхует от случая, когда прокси убивает страницу,
а выключается только в настройках внутри неё: без отметки готовности
прокси снимается и приложение перезапускается без него.

Пароль прокси лежит в файле настроек открытым текстом. Шифрования нет.

## Сборка

Три режима Vite. У `userscript` и `tauri` точка входа —
`src/userscript/main.ts`; у `app` свой корень `src/app` и выход `dist/app`.

|                 | userscript                      | tauri                            |
| --------------- | ------------------------------- | -------------------------------- |
| `@bridge-impl`  | `shared/bridge/MonkeyBridge.ts` | `shared/bridge/TauriBridge.ts`   |
| `@adblock-impl` | `shared/adblock/impl.noop.ts`   | `shared/adblock/impl.desktop.ts` |
| Формат          | сборка с шапкой юзерскрипта     | IIFE, без динамических чанков    |
| CSS             | встраивается в скрипт           | отдельный файл, вшивается в Rust |
| Очистка `dist`  | да                              | нет                              |

Сборка Rust требует обоих выходов. Порядок: `build:tauri`, `build:app`,
`cargo`.

Минификация выключена намеренно: правила Greasy Fork требуют читаемого
исходника. Динамический `import()` запрещён — в юзерскрипте ему неоткуда
грузить чанки.

Номера версий обоих продуктов живут в `versions.json` и берутся
по продукту, а не по среде: скрипт в окне Tauri — тот же скрипт.
Расхождение с номером в `package.json` роняет сборку нарочно. Теги выпуска
идут с приставкой продукта: `script-2.0.2`, `app-3.0.0`.

## Экраны приложения

Общее правило слоя: экран ничего не знает про сеть и хранение. Он читает
память через `collection-view.ts`, меняет список только через `queueEdit()`,
имена берёт у `media-title.ts`, облик — у `media-looks.ts`, а взрослое
отбирает через `adult.ts`.

### Адреса

Шесть: главная, списки, поиск, настройки, карточка тайтла и страница
студии. Последние два — с номером в адресе. Вид списка в адрес
не пишется, поэтому возврат с карточки теряет выбор.

### Тема

`styles/theme.css` — единственное место цвета, радиуса и тени. До единой
темы каждый экран красился сам и совпадал с соседом приблизительно.

Размер постера задан одним токеном `--am-tile`: полка главной и сетка
списков обязаны держать один размер, иначе переход между экранами
выглядит рывком. Обводка фокуса задана общим правилом на `:focus-visible`
и нигде не гасится: без неё переезд на пульт невозможен.

Цели нажатия не мельче 44 пикселей. Это задел под телевизор, а не вкус.

### Состав

- **HomeScreen** — витрина рекомендаций. Полки собираются через
  `api/anilist-catalog.ts`, вкус считается по жанрам записей с оценкой 8
  и выше, берутся два верхних. Скрытые рекомендации копятся
  в `am_recs_hidden` с потолком 500. Выбранная вкладка и жанр переживают
  уход с экрана через `home-keep.ts`.
- **ListsScreen** — самый сложный экран. Строки строятся в три шага
  и показываются после первого: отбор и порядок по памяти, затем облик
  пачкой, затем русские имена по десять. Картинка, ждущая всех имён,
  выглядит зависанием на большом списке. Имя без перевода показывается
  латиницей из снимка, номер — последний выход. Длинный список
  показывается сотнями, наблюдатель ловит хвост за 600 пикселей до конца,
  рядом стоит кнопка с остатком: без неё добор недоступен с пульта.
- **SearchScreen** — слово само выбирает источник: латиница идёт
  в AniList, кириллица — в Шикимори с переводом находок по номерам MAL.
  Переключателя источника нет осознанно. У русского пути нет второй
  страницы.
- **MediaScreen** — карточка. Описание одной колонкой шириной до 78 знаков
  с сохранёнными переводами строк: газетные колонки резали абзац
  по строке. Франшиза — хронология частей со Шикимори; частей, которых
  нет в AniList, в ней нет. Карточка видит две правды о записи — свою
  память и ответ сервера — и показывает свою: там лежит правка, которая
  ещё не уехала. Расхождение называется вслух отдельной подсказкой.
- **StudioScreen** — работы студии сеткой. В меню экрана нет, на него
  ведут чипы карточки.
- **SettingsScreen** — вход и выход, перенос списка, чистка местного
  списка, показ взрослого, сведения о сборке. Настройка пишется
  в хранилище сразу при переключении, без кнопки «Сохранить»: скрытая
  вторая правда о включённости тумблера хуже одного лишнего письма
  в хранилище.

### EntrySheet

Окно правки записи не держит своей памяти о ней — только черновик
комментария. Две правды об одной записи расходятся быстро, особенно
когда перенос списка приходит при открытом окне.

Комментарий — единственное поле с черновиком и единственное, что уходит
не сразу: отправка на уход из поля и на закрытие окна, чтобы очередь
не набивалась правкой на каждый символ. Закрытие любым способом —
кнопкой, фоном, Escape, размонтированием — прогоняет черновик.

## Надстройка над сайтом

### Перевод

Два независимых механизма. Интерфейс переводится словарём и правилами
без сети: сначала точное совпадение, потом шаблоны для дат, сезонов
и строк активности. Названия и имена добываются сетью и кэшем, очередями.
Русские числительные требуют трёх форм слова, поэтому в таблицах тройки.

`registerMutationHook()` — единственный наблюдатель мутаций на весь проект.

### Виджеты страницы тайтла

Каждый виджет — `{ name, cleanupSelectors, mount(ctx) }`. Три неочевидных
правила:

- виджет сам проверяет своё наличие: `mount` зовётся многократно, React
  регулярно выкидывает чужие узлы;
- каждый вызов обёрнут отдельно: падение одного виджета не убирает
  остальные;
- после каждого ожидания сети проверяется, что человек всё ещё на том же
  тайтле.

Состав: плеер, рейтинги, дерево франшизы, музыка, внешние ссылки. Порядок
регистрации в `main.ts` задаёт порядок блоков в сайдбаре.

Плеер ищет в Kodik по номеру MAL, серии переключаются без перезагрузки
кадра через `postMessage`. Запасной путь — поиск по номеру Шикимори.

### Доступность источников

Учёт идёт по идентификаторам источника: `anilist:graphql`,
`shikimori:<домен>`, `anime365:<домен>`, `animethemes`, `dictionary`.
Источник считается проблемным после двух неудач подряд. Отказ авторизации,
429 и отмена запроса не учитываются, а 404 считается успехом: сервис
ответил.

Проверка из вкладки «Разработчик» идёт последовательно, а не веером:
одновременные пробы по зеркалам ловили 429 у Шикимори.

## Внешние зависимости

| Сервис                  | За что отвечает                    | Чем заменим        |
| ----------------------- | ---------------------------------- | ------------------ |
| `graphql.anilist.co`    | каталог, списки, правки            | ничем              |
| `shikimori.io`          | русские имена, люди, франшизы      | датасетом частично |
| `anime365.ru`           | русские названия и описания        | датасетом частично |
| `kodik-api.com`         | видео                              | ничем              |
| `api.animethemes.moe`   | музыкальные темы                   | необязателен       |
| `raw.githubusercontent` | словарь интерфейса                 | вшитой копией      |

Ключ Kodik вшит в код: он публичный и выдаётся сайту, а не пользователю.

Словарь тянется с ветки `main` напрямую, без прокси и без запасного
адреса — единственное обращение в сети, которое обходит `net-health.ts`.
Это же станет образцом для датасета названий, и там запасной путь
обязателен.
