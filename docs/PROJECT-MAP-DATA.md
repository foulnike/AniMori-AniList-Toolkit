# Карта проекта, часть 5: слой данных

Продолжение `PROJECT-MAP-SHELL-2.md`. Здесь хранение данных пользователя
и слой данных целиком. Темп обращений и паузы — в части 7
(`PROJECT-MAP-NET.md`), подсистемы моста и файлы — в частях 2 и 4, оболочка —
в части 3, свои экраны — в части 6.

---

## Хранение

Три места, и различает их цена потери.

| Что                             | Где                          | Если потеряется          |
| ------------------------------- | ---------------------------- | ------------------------ |
| Ответы сети, русские карточки   | IndexedDB (`db.ts`)          | добудется заново         |
| Снимок списка и очередь правок  | хранилище моста              | правки взять негде       |
| Второй экземпляр снимка         | файл приватного каталога     | остаётся главный        |

Базы приложения нет вовсе: список приходит двумя запросами, аниме и манга,
и укладывается в память. Обмена между устройствами нет. Без подключённого
сервиса список — полноценный местный; как только сервис подключён, источником
истины становится он и его состояние затирает местное. Причины и границы
курса — в `docs/DECISIONS-LISTS.md`.

### db.ts — склад ответов

Три стора: `shikiCache` (ключ-строка), `malCache` и `franchiseCache` (ключ-число),
версия базы — 5. Миграции идут по номеру версии, шаги идемпотентны. Открытие
разрешается всегда и ровно один раз: соединением, `null` по ошибке или `null`
по таймауту. Работа без кэша медленна, но это работа; висящий старт —
мёртвое приложение.

Соединение снимает само себя при `versionchange` и `close`, иначе в памяти
остался бы битый экземпляр до конца сеанса. Сборщик мусора вызывается,
но выходит сразу: срок жизни задан бесконечным. Русские имена и облик
тайтла лежат в том же сторе с префиксами `RU1_` и `LOOK2_` — к Шикимори
второй префикс отношения не имеет, это долг имени.

### snapshot.ts — снимок и очередь

Две записи в хранилище моста: `AM_SNAPSHOT` и `AM_EDIT_QUEUE`.

Запись снимка знает о тайтле всё, что показывают экраны, включая метку
взрослого и оба латинских имени. Латиница лежит в самом снимке: иначе
список до прихода русских имён показывал бы номера. Даты хранятся строкой
`ГГГГ-ММ-ДД` — нечёткая дата AniList в `Date` не ложится, а строки
сравниваются в верном порядке.

Номер версии снимка растёт при любом новом поле записи: снимок читается
целиком, и старая запись без поля выглядела бы стёртым значением. Цена роста —
один перенос списка с сервиса.

Снимок пишется и читается целиком одной записью — атомарность вместо
транзакций. Чужая версия и битый разбор дают пустой снимок, отдельные
битые записи отбрасываются поштучно. Рядом лежит номер владельца: без него
после смены учётной записи показали бы чужой список. Пустой номер значит
местного владельца: список без входа — тоже список.

Хозяин один: `ownSnapshot()` принимает поставщика, второй пишущий отклоняется.
Запись откладывается на две секунды — прокрутка списка меняет память десятками
правок в секунду. Точек немедленного сохранения две: уход в фон
(`visibilitychange`) и `pagehide`. Не `beforeunload`: в WebView он часто не приходит.

Очередь правок пишется немедленно и целиком: это единственные данные, которые
негде взять заново. Видов правки девять — закладка, оценка, прогресс, тома,
пересмотры, две даты, комментарий и удаление. Старые правки вытесняются
по потолку. У правки свой идентификатор, а не серверный: отметить принятой
надо именно отправленную. Снимок и очередь идут одной цепочкой записи —
параллельные записи обгоняют друг друга и теряют хвост. В том же звене снимок
кладётся вторым экземпляром в файл (часть 4); читается файл только при пустом
хранилище, отказ файла идёт в журнал и ничего не роняет.

## Слой данных

Порядок пуска держит `app/main.ts`: сначала `loadSettings()`, затем
`initCollection()` — подъём снимка и накат очереди, затем `startEditSender()`.
Перенос списка с сервиса сам на старте не идёт: только по действию человека,
потому что он замещает список целиком. Экраны меняют список только через
`queueEdit()`, имена берут у `media-title.ts`, облик — у `media-looks.ts`,
а взрослое отбирают через `adult.ts`.

```
экраны
  ├─ collection-view.ts  отборы и счётчики (только чтение)
  ├─ adult.ts            единый отбор 18+ → settings.ts
  ├─ edit-sender.ts      queueEdit → collection.ts → snapshot.ts
  ├─ media-title.ts      русские карточки → db.ts, api/shikimori-*.ts
  ├─ media-looks.ts      обложка, цвет, части → db.ts, api/anilist-lookup.ts
  └─ media-search.ts     поиск по своему списку и по чужому каталогу
collection.ts  ← api/anilist-list.ts
edit-sender.ts → api/anilist-edit.ts
```

### collection.ts — хозяин списка

Записи держатся словарём по номеру тайтла: карточка и каждая правка ищут
запись по номеру, а обход тысяч записей на приставке виден глазом. Ответ
сервера — основа, неотправленные правки накатываются сверху, иначе оценка
откатилась бы на глазах. Обновление замещает спрошенные типы целиком:
сервис — источник истины, а удалённое там не должно жить в памяти навечно.
Идёт оно по типам, по умолчанию по обоим, и только по прямому действию
человека: автоматический заход при открытии экрана стирал бы правки втихую.
Без входа переносить неоткуда, и слой говорит это прямо. Смена входа чистит
память, второе обновление ждёт идущее. Отвязка счёта оставляет записи на месте
и только снимает хозяина; полная чистка — отдельное действие. Правка
неизвестного тайтла создаёт пустую запись (`blankEntry`) — так выглядит
добавление, которого сервер ещё не видел.

Долг: понятия «подключённый сервис» в ядре нет — есть только номер хозяина
AniList. Замок на один сервис и замена списка при переключении ждут слоя
поставщика списка (пункты 8.5, 8.6 и 8.13 плана).

### collection-view.ts — отборы

Только чтение памяти. Условие отбора одно на перебор, подсчёт и страницу:
расхождение выглядело бы как ошибка чисел у закладок. Перебор ленивый,
выдача отдаёт ссылки на записи, а не копии. Сортировка только по полям
снимка; порядок по имени экран считает сам после добора имён. Ноль оценкой
не считается: так AniList отдаёт «оценки нет». Запись без статуса попадает
в `UNKNOWN`.

### adult.ts — единый отбор взрослого

Одно место решает, видна ли взрослая карточка: включён ли показ, разрешён ли
тайтл, отбор набора и счёт спрятанных. Состояние одно — настройка `showAdult`
(ключ хранилища `set_adult`, по умолчанию выключено). Из баз и со сервера
взрослое не вырезается никогда: иначе запись в своём списке исчезала бы вместе
с оценкой. Скрытое считается, чтобы экран мог сказать число вслух,
а не тихо терять находки. Долг: полки главной и похожее отбора ещё не зовут.

### edit-sender.ts — отправка правок

Единственный путь изменений на сервер. `queueEdit()` меняет память, пишет
очередь и толкает разбор; без входа очередь не набивается вовсе — правка
живёт местно. Отправщик поднимается на старте из `app/main.ts`: иначе фоновый
разбор и повтор на событие `online` мертвы, и уходит только то, что успело
отправиться сразу. Разбор идёт строго по порядку и в одном потоке: две правки
одного тайтла местами менять нельзя. Пустая строка в правке дат и комментария
значит «стереть». Отказ по содержанию выкидывает свою правку — иначе одна
плохая запись заперла бы очередь навсегда; временная помеха останавливает
весь разбор до следующего захода. Попытка засчитывается только при ответе
сервера; после пяти попыток правка бросается с записью в журнал — при
двусторонней связи это заметная потеря и ждёт решения. Заходы: раз в минуту
и на событие `online`; пока стоит общая пауза AniList, разбор не начинается.
Сейчас файл знает только AniList.

### media-title.ts и media-looks.ts

Первый даёт русские имена и описания. Путь чтения трёхуровневый: память
запуска, склад (`RU1_`), сеть. В памяти запоминается и отсутствие перевода,
иначе каждая перерисовка била бы в сеть за тем же отказом; сетевой сбой
не запоминается. Пачка добывается по очереди, а не веером: сотня
одновременных запросов сразу упирается в темп.

Второй даёт облик: обложку, цвет, формат, год, число частей, общую оценку
и оба латинских имени. Склад — `LOOK2_`, пачка — по пятьдесят номеров. Облик
отделён от русских имён: источники разные, и терять обложки при отказе
Шикимори незачем. Метки взрослого облик не несёт — её берут из снимка
или из находки поиска.

### media-search.ts — поиск

Две разные задачи в одном файле. Поиск по своему списку идёт по памяти
и смотрит русское имя, ромадзи и английское: свой список искать в сети
незачем, и он работает без сети вовсе. Поиск по каталогу спрашивает AniList,
а на кириллице идёт через Шикимори и его номера MAL: AniList по-русски
не ищет. Находки просеиваются через `adult.ts`, число скрытых идёт в журнал.
Долг: `isRussianWord` выведен наружу, но его никто не зовёт.

### Запросы: api/anilist-*.ts

Список — `anilist-list.ts`: кто вошёл и вся коллекция одного типа одним
запросом. Шкала оценки задана в самом запросе, а не взята из настроек
пользователя: иначе одна запись приходит то как 85, то как 8.5. Деление
на подборки сайта не сохраняется: дубли схлопываются по номеру тайтла,
запись без номера отбрасывается.

Правки — `anilist-edit.ts`. Незаданные поля в мутацию не кладутся вовсе:
переданный `null` стёр бы поле, которого не трогали; различие «не трогали»
и «стереть» решается наличием ключа. Удаление стоит двух запросов — сервер
удаляет по номеру записи списка, а в памяти лежит номер тайтла. Ответ сводится
к одному вопросу: повторять или бросить.

Карточка и выписки — `anilist-media.ts` и `anilist-lookup.ts`: мостик AniList → MAL,
полная карточка, поиск и краткие выписки пачками по пятьдесят — таков потолок
страницы, а поодиночке темп сгорит. Выписка полей своей записи не просит
и ставит их пустыми: правда о записи живёт в снимке. Тип записи у двух
файлов общий, поэтому новое поле надо дописывать в обоих строителях.
