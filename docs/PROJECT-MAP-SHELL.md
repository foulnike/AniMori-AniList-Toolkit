## 9. Оболочка Tauri (`src-tauri/`)

### Главная особенность

Окна двух родов, и разница между ними важнее всего остального в этой части.
Окно `main` грузит свою сборку из `dist/app` — это локальный фронтенд.
Окно `site` — браузер одного сайта: живой anilist.co со встроенной
надстройкой, запасной вид на время, пока свои экраны неполны.

Отсюда три следствия:

1. оба окна создаются кодом, а не в `app.windows` конфига (там пустой
   список): окну с сайтом нужны внешний адрес и скрипты инициализации;
2. разрешения разведены по двум файлам: `capabilities/default.json` для своего
   окна, `capabilities/site.json` для окна с чужим доменом;
3. внешние ссылки перехватываются в `on_navigation` и уходят в системный браузер,
   иначе окно уехало бы на сторонний сайт без адресной строки
   и кнопки назад.

### lib.rs

- окно `main` на своей странице из `dist/app`, размер 1280×800, минимум 1024×600;
- команды: перезагрузка окна, переключение полного экрана, открытие внешнего
  адреса (схема проверяется: только http и https), состояние и щуп прокси,
  отметка готовности страницы, вход AniList, открытие запасного вида;
- плагины: store, http, clipboard-manager, opener, dialog, window-state, updater;
- блокировщик и авторизация у прокси ставятся только под Windows;
  проверка обновлений запускается последней, чтобы не тормозить показ окна.

Положение и размер окна запоминаются между запусками (состояние окна:
размер, позиция, развёрнутость).

### hybrid.rs

Окно `site` с меткой и правами отдельного файла разрешений. Открывается
командой `animori_open_site` без параметров: адрес зашит, иначе чужой код
открывал бы в нашем окне любой сайт.

Бандл и стили надстройки вшиваются в двоичный файл через `include_str!`
из `dist/` и отдаются окну скриптами инициализации: сначала стили, затем
сам скрипт. Поэтому `npm run build:tauri` обязателен до `cargo`: без бандла
в `dist` сборка Rust падает на чтении файла, а не на логике.

Скрипт сетевой разведки выполняется только во вложенных кадрах и молчит,
пока его не включат командой. Сторож прокси заводится здесь же, при открытии
окна с сайтом.

### auth.rs

Вход AniList без системного браузера: форма открывается в окне с меткой
`login`, которое живёт в общем окружении движка и идёт через наш прокси.
Сайт недоступен из РФ, а нашего прокси внешний браузер не знает.

Пропуск возвращается на `http://127.0.0.1:48513/relay`. Приёмник слушает только
петлю, сам отдаёт страничку-стрелочник и гаснет через пять минут.
Пропуск в разметку не попадает: её часть — только факт входа и срок.
Ручная вставка остаётся запасным путём на случай, если возврат не дойдёт.

Окна создаются только из рабочего потока, поэтому все команды открытия
асинхронные: в главном потоке `build()` ждёт сам себя и окно висит пустой
рамой. Адреса склеиваются `concat`, встроенный JS — `concat!`.

### Три места для новой команды

1. `#[tauri::command]` и `invoke_handler` в `lib.rs`;
2. `AppManifest::commands` в `build.rs`;
3. разрешение в нужном файле `capabilities/`.

Пропуск третьего пункта даёт отказ в рантайме без ошибки компиляции — самый
неприятный вариант. Если команда вызывается из фронтенда, мест становится
четыре: тип в `IBridge`, реализация в `TauriBridge`, заглушка в `MonkeyBridge`
и сама команда. Заглушка обязательна: без неё браузерная сборка падает
на тайпчеке. Мост лежит в `src/shared/bridge/`.

### adblock.rs

Сетевой фильтр на событиях WebView2: запросы к рекламным хостам отбиваются
до выхода в сеть. Списки собраны вручную, без внешнего движка фильтров:
полноценный движок был в планах и остался открытым пунктом.

### proxy.rs, proxy_auth.rs и proxy_guard.rs

Трафик десктопа идёт двумя независимыми каналами, и прокси настраивается
для каждого своим способом: страница — через ключи запуска WebView2
(`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`), запросы из Rust — через опцию клиента.
Ключи WebView2 читаются один раз при создании первого окна, поэтому решение
о прокси принимается до него, а смена настройки требует перезапуска.

`proxy.rs` сводит всё к одному исходу: выключено, неверные данные, адрес
не отвечает, применено. Исход хранится в состоянии и отдаётся интерфейсу
командой: молчаливое применение нерабочего прокси выглядит как поломка
приложения.

`proxy_auth.rs` подставляет логин с паролем на событие базовой авторизации
WebView2, только под Windows: ключом запуска их не передать, а без обработчика
запрос отменяется молча. Событие одно и на 407 от прокси, и на 401 от сайта,
поэтому три предосторожности: адреса из списка исключений пропускаются,
больше пяти попыток подряд не делается, каждая подстановка пишется
в журнал с хостом. Повторный запрос считается признаком неверного пароля:
кода ошибки в событии нет. Наши запросы к API сюда не попадают: у них своя
авторизация в `TauriBridge.ts`. Старый рантайм остаётся без этой возможности,
приложение не падает.

`proxy_guard.rs` страхует от самой неприятной ситуации: прокси убивает страницу,
а выключается оно только в настройках внутри этой страницы. Фронтенд
отмечается готовым после монтирования; если отметки нет в течение двенадцати
секунд, прокси снимается и приложение перезапускается без него. Живая
страница заодно сбрасывает счётчик попыток авторизации.

### tauri.conf.json

Идентификатор `com.foulnike.animori`; страница окна берётся из `dist/app`;
версия — из `package.json`, куда номер приложения дублируется из `versions.json`;
бандл только nsis; обновления тянутся из последнего релиза GitHub
по `latest.json` и проверяются по публичному ключу; установка в тихом режиме.

Подпись обязательна: без переменных окружения с приватным ключом и паролем
сборка релиза не пройдёт, иначе автообновление отвергнет пакет.
При разработке помогает `npm run tauri build -- --no-bundle`.

## 10. Сборка (`vite.config.ts`)

Три режима. У двух первых точка входа — `src/userscript/main.ts`, у третьего
свой корень `src/app` и выход `dist/app`.

|                 | userscript                      | tauri                            |
| --------------- | ------------------------------- | -------------------------------- |
| `@bridge-impl`  | `shared/bridge/MonkeyBridge.ts` | `shared/bridge/TauriBridge.ts`   |
| `@adblock-impl` | `shared/adblock/impl.noop.ts`   | `shared/adblock/impl.desktop.ts` |
| Формат          | сборка с шапкой юзерскрипта     | IIFE, без динамических чанков    |
| CSS             | встраивается в скрипт           | отдельный файл, вшивается в Rust |
| Очистка `dist`  | да                              | нет (рядом лежит юзерскрипт)     |

Режим `app` собирает свои экраны обычным приложением Vue и берёт те же
алиасы среды, что и `tauri`: свое окно живёт в той же среде.

Сборка Rust требует обоих выходов: своё окно берёт `dist/app`, а окно с сайтом —
бандл скрипта из `dist` через `include_str!`. Порядок такой: `build:tauri`,
затем `build:app`, затем `cargo`.

Кроме этого в конфиге живут алиасы совместимости — старые имена модулей
ведут на новые каталоги (таблица в части 1). Они обязаны совпадать
с `paths` в `tsconfig.json` и `tsconfig.shared.json`: расхождение даёт зелёную
сборку при красном тайпчеке или наоборот.

Минификация выключена намеренно: правила Greasy Fork требуют читаемого
исходника. Динамический `import()` запрещён: в юзерскрипте ему неоткуда
грузить чанки.

Номера версий обоих продуктов живут в `versions.json` и берутся по продукту,
а не по среде: скрипт в окне Tauri — тот же скрипт. Номер приложения
дублируется в `package.json`, откуда его берёт Tauri, и расхождение роняет
сборку нарочно. Номер попадает в код как `__ANIMORI_VERSION__` через `define`
и используется в `User-Agent` запросов десктопа. Теги выпуска идут
с приставкой продукта: `script-2.0.2`, `app-3.0.0`.

Скрипты: `dev` и `dev:app` для разработки; `build` (тайпчек плюс юзерскрипт),
`build:app`, `build:tauri`; `tauri:dev`, `tauri:build`; `typecheck`,
`typecheck:shared` (граница ядра) и `typecheck:all`, который стоит в обоих
сборках; `format`. Неиспользованный импорт роняет тайпчек, а значит
и сборку. `README.md` и `CHANGELOG.md` выведены в `.prettierignore`:
форматтер ломал их разметку.

После любой правки конфига сборки сверяется число модулей и размер вывода:
резкое изменение обычно означает, что в бандл уехало лишнее.

Два списка разрешённых адресов живут отдельно и оба обязательны: `connect`
в шапке юзерскрипта (`vite.config.ts`) и разрешения http в
`src-tauri/capabilities/default.json`. Новый внешний адрес без записи в обоих
работает только в одной из сборок.

## 11. Данные

### Хранилище ключ-значение (через мост)

Группы ключей:

- авторизация и учётные данные: токен AniList, логин Shikimori;
- настройки с префиксом `set_`: перевод и его источники, виджеты, внешние
  ссылки и их домены, журнал, блокировка всплывающих окон плеера, адблок,
  видимость кнопок переноса и сравнения, прокси;
- пользовательские данные с префиксом `am_`: личный словарь, свои ссылки,
  избранные озвучки, акцент, сервис музыки;
- служебное: список игнора сравнения, записи журнала.

В браузере это хранилище Tampermonkey, в десктопе — файл в профиле пользователя.
Общего синхрона между сборками нет: это два независимых набора настроек.
Пароль прокси лежит в этом же файле открытым текстом — шифрования нет.

### IndexedDB

`malCache` — ответы AniList по id; `shikiCache` — карточки Shikimori с меткой
времени. Срок годности 90 дней. Кэш чистится фоновым сборщиком и кнопкой
в настройках — кнопка требует второго нажатия для подтверждения.

### Внешние сервисы

AniList GraphQL, Shikimori и его зеркала, Anime365, AnimeThemes, Kodik,
raw.githubusercontent для словаря. Ключ Kodik вшит в код — он публичный
и выдаётся сайту, а не пользователю.

## 12. Инварианты кодовой базы

Короткий список правил, нарушение которых уже приводило к дефектам.

1. Мост импортируется только как `@/bridge`, адблок — только как `@adblock-impl`.
2. Между слоями импорт только алиасом; относительные пути — только внутри
   своего каталога.
3. Платформенный модуль выходит проверкой платформы на первой строке, а не
   разводит ветки по всему файлу.
4. Каждый сетевой запрос берёт слот у ограничителя темпа и явно задаёт
   `credentials`.
5. Молчаливый `catch` запрещён: либо обработка, либо запись в журнал.
6. Селекторы берутся из живого DOM, а не из предположений о разметке сайта.
7. Чужие узлы прячутся, а не удаляются.
8. Тумблер видимости не отменяет монтирование компонента.
9. Вложенные реактивные ссылки объявляются поверхностными.
10. Задачи смены роута идемпотентны.
11. Шапка юзерскрипта не расширяется новыми разрешениями без крайней
    необходимости: каждое право проверяется модерацией Greasy Fork.
12. Настройка, способная убить страницу, не управляется только из этой
    страницы: нужен внешний выход из оболочки.
