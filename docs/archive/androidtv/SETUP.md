# Настройка среды для порта на Android TV

Разовая настройка. Записана целиком, включая грабли: половина времени ушла
именно на них, а не на установку.

## Что установлено

Android Studio, сборка `android-studio-quail3-patch1`, стоит в
`D:\Android\Android Studio`.

Компоненты SDK (`C:\Users\Nike\AppData\Local\Android\Sdk`):

- `platform-tools` 37.0.1 — здесь лежит `adb`
- `platforms;android-37.0`
- `build-tools;36.0.0`
- `ndk;30.0.15729638` — компилятор родного кода, без него Rust не собрать
- CMake
- Command-line Tools
- `sources;android-37.0` и эмулятор — не нужны, но вреда нет

Отдельно поставлен Temurin JDK 21:

```powershell
winget install --id EclipseAdoptium.Temurin.21.JDK -e
```

## Переменные среды

Ставятся один раз, на уровне пользователя:

- `ANDROID_HOME` = `C:\Users\Nike\AppData\Local\Android\Sdk`
- `NDK_HOME` = `C:\Users\Nike\AppData\Local\Android\Sdk\ndk\30.0.15729638`
- `JAVA_HOME` = `C:\Program Files\Eclipse Adoptium\jdk-21.0.12.8-hotspot`
- в `Path` добавлена папка `platform-tools`

Java нужна не нам, а Gradle — сборщику Android. Сначала указали Java из
Android Studio (папка `jbr`, там OpenJDK 25.0.2) и сборка упала. Проверка:
`java -version` в новом окне должна показать 21.

## Цели Rust

```powershell
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
```

Цель выбирает не наше желание, а само устройство: наш телевизор просит
`armv7-linux-androideabi`, то есть прошивка у него 32-битная. Остальные цели
добавлены на случай эмулятора и других приставок.

## Телевизор

Haier Android TV DVB, стоит над компом, подключён по HDMI. HDMI даёт только
картинку с компа, отладка по нему не ходит: приложение ставится по сети
через `adb`.

На телевизоре: «Об устройстве» → семь нажатий по «Сборка» → появится меню
«Для разработчиков» → включить отладку и отладку по Wi-Fi.

Адрес телевизора: `192.168.1.38`.

Подключение делается в два приёма, порты **разные**:

```powershell
adb pair 192.168.1.38:35199
adb connect 192.168.1.38:33333
adb devices
```

Порт сопряжения показывается на экране «Подключение по коду сопряжения»
вместе с шестизначным кодом, рабочий порт — на главном экране отладки по
Wi-Fi. Оба порта телевизор меняет, каждый раз смотреть на экране.

Признак успеха: в `adb devices` устройство помечено `device`.

## Грабли, на которые уже наступили

- **Порт 5555 не работает.** Отладка по Wi-Fi выдаёт случайный порт.
  `adb connect` на 5555 отвечает `connected`, но список устройств пуст:
  соединение принято, разговора нет.
- **`failed to authenticate`.** Телевизор запомнил отказ и перестал
  спрашивать. Лечение: на телевизоре отозвать разрешения отладки, на компе
  удалить `%USERPROFILE%\.android\adbkey` и `adbkey.pub`, перезапустить
  сервер. Новый ключ телевизор принимает за новый компьютер и спрашивает
  снова.
- **Диалог доверия появляется только на разбуженном экране.** На спящем
  телевизоре его не видно, и подключение молча не проходит.
- **Перезапуск сервера `adb` рвёт сетевое подключение.** Признак:
  `daemon started successfully`, а следом `device ... not found`. Лечение:
  снова `adb connect`, сопряжение не требуется, ключ телевизор помнит.
- **Две записи в `adb devices` — один телевизор.** Найден по адресу и по
  имени в сети. Инструменты иногда ругаются на «больше одного устройства»,
  тогда указывать адрес явно.
- **`adb` не в `Path` после установки SDK.** Добавляется вручную.
- **Компоненты SDK ставятся не в «Plugins», а в SDK Manager.** Плагины —
  дополнения к редактору. Нужный экран: Settings → Languages & Frameworks →
  Android SDK, вкладка SDK Tools, галочка Show Package Details.
- **Новые переменные среды видят только новые окна PowerShell.** Дважды
  потеряли на этом время: `JAVA_HOME` был записан, но в открытом окне
  оставался пустым, и путь превращался в `\bin\java.exe`.
- **Пути с пробелами только в кавычках**: и `Android Studio`, и наши папки.
- **Java 25 из Android Studio не годится.** Gradle 8.14.3 спотыкается о
  номер версии и падает без объяснений: `A problem occurred configuring
  project ':buildSrc'` и одна строка `> 25.0.2`. Лечение — JDK 21.
- **Список устройств выбирается номером строки.** На вопрос `Device:`
  вводится `0`, адрес там не понимается: `Hey, that wasn't a number!`
- **Устройство в команде задаётся частью имени, а не адресом.** Флага
  `--device` у команды нет вовсе, с ним будет `unexpected argument`.
  С адресом вместо имени будет `No available Android Emulator detected`.
  Верно: `npm run tauri android dev -- Haier`.
- **`Blocking waiting for file lock`** — папку сборки держит другой
  процесс: открытая Android Studio или прошлый недобитый прогон. Закрыть
  студию и `Get-Process cargo, rustc, java | Stop-Process -Force`.
- **`BUILD SUCCESSFUL` в Android Studio ничего не ставит на телевизор.**
  Студия только собирает apk, установку и запуск делает `tauri` через
  `adb`. Проверка, что пакет на месте:
  `adb -s 192.168.1.38:33333 shell pm list packages | Select-String animori`
- **Kotlin-демон падает, потому что проект на `D:`, а кэш cargo на `C:`.**
  В логе полотно `IllegalArgumentException: this and base files have
  different roots`. Сборка сама переходит в обходной режим «без демона» и
  доходит до apk, так что это шум, а не ошибка. Цена — десятки лишних
  секунд. Радикальное лечение — держать проект на том же диске, что кэш.
- **VPN на этот случай был не виноват**, но при разработке может помешать:
  телевизор должен дотянуться до сервера на компе. Если не видит —
  выключить.
- **Адрес сервера разработки выбирается автоматически и может быть
  виртуальным.** В логе было `Using 172.18.0.1` — адаптер Docker или WSL,
  до которого телевизор не дотянется. Нашему окну сервер не нужен:
  интерфейс вшит в бинарник через include_str!. Если всё же понадобится —
  задать `TAURI_DEV_HOST` с настоящим адресом компа в локальной сети.

## Что создал `tauri android init`

Папку `src-tauri/gen/android`: проект для Android Studio с обёрткой на
Kotlin, которая создаёт окно с webview и подключает нашу Rust-библиотеку.
Наш код не переносится, обёртка его вызывает.

Папка целиком в `.gitignore`, `git status` после генерации пуст. Отсюда
будущая задача: правки манифеста для телевизора попадут в игнорируемую
папку и потеряются. Решение выбирается в пункте 3.3 плана.

## Запуск на телевизоре

```powershell
cd "D:\Renforge\Animori TV"
npm run tauri android dev -- Haier
```

Первая сборка идёт десять-двадцать минут: Rust собирает всю свою часть
заново под другой процессор. Дальше кэш, быстрее.

Признаки, что всё дошло до конца: `Performing Streamed Install`, `Success`
и `Starting: Intent { cmp=com.foulnike.animori/.MainActivity }`.

Смотреть логи приложения: `adb logcat`. Отлаживать саму страницу: Chrome на
компе, адрес `chrome://inspect`. Зеркалить экран телевизора в окно на
компе: `scrcpy`, ставится через `winget install scrcpy`. Фокусную навигацию
всё равно проверять живым пультом: мышью себя обманем.

Плитка Animori в списке приложений появилась, серая и без оформления:

выход через пять-шесть секунд. Это пункт 1.5 плана, разбирается по
