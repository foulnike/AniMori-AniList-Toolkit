# Соглашения

Правила, по которым живёт код и документация приложения. За большинством пунктов
стоит дефект, который уже случился.

---

## Слои и зависимости

```
app/                    экраны, компоненты, роутер
        ↓
shared/api/ → shared/bridge/
        ↓          ↓
  shared/core/ ←───┘
        ↓
  shared/utils/
```

- `shared/` не знает о `app/`. Проверяется отдельной сборкой: `npm run typecheck:shared`
  собирает ядро в мире, где каталога `src/app` не существует, и падает на любой
  стрелке из ядра в надстройку.
- Граница нужна не для красоты. Ядро живёт сразу в двух ветках — здесь
  и в `script`, — и перенос правки между ними остаётся дешёвым только пока ядро
  не знает, в какой оболочке работает. Как переносить — в `REPO-LAYOUT.md`.
- Между слоями импорт только алиасом, относительные пути — внутри своего
  каталога.
- К `@tauri-apps/*` никто не обращается напрямую, только через мост: `@/bridge`
  за типами, `@bridge-impl` за реализацией.
- Сетевые вызовы живут только в `shared/api/`. Экран, стучащий в сеть сам,
  обходит ограничитель темпа и рано или поздно ловит 429.
- `shared/utils/` не импортирует ничего, кроме типов.
- Экран не ходит в сеть и в хранилище сам, только через слой данных.

Остатки разделения соглашением не считаются. В ядре могут ещё попасться
ссылки на то, чего в этой ветке нет — например на `NO_TRANSLATE_CLASS`
переводчика, который остался юзерскрипту. Такое убирается при первой же
правке файла, а не копируется дальше как образец.

## Инварианты

Нарушение каждого уже приводило к дефекту.

1. Каждый сетевой запрос берёт слот у ограничителя темпа и задаёт
   `credentials`. Для `graphql.anilist.co` всегда `omit`: с куками сервис
   отвечает 403 через Cloudflare.
2. Молчаливый `catch` запрещён. Либо обработка, либо запись в журнал.
3. Список меняется только через `queueEdit()`.
4. Взрослое отбирается только через `adult.ts` и только на слое показа.
   Из баз и с сервера оно не вырезается никогда.
5. Вложенные реактивные ссылки объявляются поверхностными.
6. Задачи смены роута идемпотентны.
7. Цвета и радиусы — только токенами темы.
8. Настройка, способная лишить программу связи, не управляется только
   из того места, которое без связи не откроется. Прокси — ровно такой
   случай: экран настроек обязан открываться на локальных данных.
9. Новый внешний адрес прописывается в разрешениях http в
   `capabilities/default.json`. Прежде таких мест было два — второе,
   `connect` в шапке юзерскрипта, ушло вместе со скриптом.
10. Новая команда оболочки заводится в трёх местах: `#[tauri::command]`
    и `invoke_handler` в `lib.rs`, `AppManifest::commands` в `build.rs`,
    разрешение в `capabilities/default.json`. Пропуск третьего даёт отказ
    в рантайме без ошибки компиляции.
11. Для вызова команды из разметки добавляются тип в `IBridge`, реализация
    в `TauriBridge` и заглушка в `MonkeyBridge`. Заглушка нужна, пока в союзе
    платформ жива `'userscript'`: без неё падает тайпчек ядра.

## Размер файла

Потолок — 25 КБ, и он касается только исходников. Причина техническая,
а не эстетическая: правки через API рвутся на файлах крупнее, и текст
молча теряет середину. Это уже случалось с `proxy.rs` (`e5e109a`).

За потолком сейчас один файл:

| Файл                    | Размер |
| ----------------------- | -----: |
| `src-tauri/src/auth.rs` | 26 482 |

Ближе всего к потолку `shared/core/snapshot.ts` (23 864), `app/screens/media-card.ts`
(23 558) и `shared/core/db.ts` (22 595): следующая крупная правка любого
из них начинается с разрезания.

Разделение продуктов эту таблицу почти обнулило. `MediaScreen.vue` был
45 762, стал 11 608; `ListsScreen.vue` — был 25 646, стал 18 440. Не потому,
что их резали, а потому что из них ушла манга и всё, что относилось
к чужой странице.

### На документацию потолок не распространяется

Резать справочник по размеру — ровно та ошибка, из которой выросли
карта проекта из семи частей и шесть файлов решений. Разложенный
по кускам справочник читается хуже цельного.

Под исключение сейчас попадают `DECISIONS.md`, `DATA-PIPELINE.md`
и `ARCHITECTURE.md`. Риск разрыва при записи от этого не исчезает,
поэтому взамен три требования:

- большой документ перезаписывается целиком одной операцией,
  а не серией частичных правок;
- после записи его надо перечитать: разрыв не даёт ошибки — запись
  отвечает успехом и теряет середину молча;
- если целиком в одну запись он уже не влезает, правка делается
  локально в рабочем дереве и приезжает обычным коммитом.

## Комментарии

Комментарий объясняет причину, а не действие. «Увеличиваем счётчик»
не нужно никому; «счётчик общий на зеркала: лимит считается по IP»
нужно всем.

Жёстких потолков на длину комментария нет. Они были защитой
от рвущихся при записи файлов, то есть лечили инструмент через стиль.
Резать надо файлы, а не мысли.

Что запрещено:

- Хронология в комментарии: «правка после…», «статус на дату», «пункт 4.5».
  История живёт в git, комментарий описывает настоящее.
- Комментарий, повторяющий имя функции.
- Закомментированный код. Он есть в истории.

Длина строки — 100 знаков. Форматирование — `npm run format`.

## Работа с репозиторием

Рабочая ветка — `app-3.0-dev`. Ветка `script` живёт своей жизнью, `main`
заморожен и не правится. Сливать ветки между собой нельзя —
`REPO-LAYOUT.md`.

Перед коммитом прогоняется `npm run format`. Тайпчек звать отдельно
не нужно: `build:app` сам начинает с `typecheck:all`. Неиспользованный
импорт роняет тайпчек, а значит и сборку.

Тело коммита — три-восемь строк о том, что было не так и что отвергнуто.
Заголовок описывает результат, тело — причину.

Правка ядра делается отдельным коммитом, не смешиваясь с правками
экранов: так её можно перенести в ветку `script` заплаткой. Смешанный
коммит переносится только руками.

Алиасы слоёв живут в трёх местах и правятся только вместе: `resolve.alias`
в `vite.config.ts`, `paths` в `tsconfig.json` и в `tsconfig.shared.json`.
Расхождение даёт зелёную сборку при красном тайпчеке или наоборот.

## Документация

Документ описывает состояние, а не хронику. Устаревшее удаляется,
а не зачёркивается: история уже есть в git.

Из этого следует:

- **Документация ветки описывает только её продукт.** Про соседний — ровно
  столько, сколько нужно для решений в этом: граница ядра, перенос
  правок, судьба словаря. Если абзац можно целиком отдать другому
  продукту — он живёт не здесь.
- **Нет файлов с номерами.** Если документ разросся, значит в нём лежит
  то, что уже неправда. Надо чистить, а не заводить следующий по счёту.
- **Нет дат в заголовках разделов.** Дата нужна ровно один раз —
  в строке отмены, чтобы понять, что чему предшествовало.
- **Нет пометок «отменено».** Отменённое стирается, а причина отмены
  переезжает в актуальную запись.
- **Причина ценнее формулировки.** Через полгода возвращаются за «почему»,
  а не за «что». Короткая запись, смысл которой забыт, бесполезна ровно
  так же, как её отсутствие.
- **Размер не повод делить.** Повод делить — только другая предметная
  область.

Список документов и вопросов, на которые они отвечают, — в `README.md`
этой папки. Новый файл появляется только с новой предметной областью;
новый месяц предметной областью не считается.
