# AniMori — приложение для AniList

**Настольный клиент [AniList](https://anilist.co) для Windows со своим интерфейсом: списки, поиск, страницы тайтлов и студий — по-русски, без браузера и менеджера скриптов.**

**AniMori** — отдельная программа, которая работает с AniList напрямую: сама запрашивает данные, сама рисует экраны и подтягивает русские названия и описания с Shikimori и anime365.

Прежний десктоп 2.x был устроен иначе — окно с сайтом `anilist.co`, в которое сборка вшивала тот же юзерскрипт. От этой схемы отказались: полный экран, модель фокуса и оформление внутри чужой страницы нам не принадлежали. Версия 3.0 — свой интерфейс от начала до конца.

AniMori — неофициальный проект и не связан с командой AniList.

> [!NOTE]
> **Где что лежит.** У проекта два продукта, и живут они в разных ветках:<br>
> — ветка **`app-3.0-dev`** (эта) — настольное приложение со своим интерфейсом, теги вида `app-3.0.0`;<br>
> — ветка **`script`** — юзерскрипт для Tampermonkey, теги вида `script-2.1.0`;<br>
> — ветка **`main`** — история монолита 2.x, когда скрипт и десктоп собирались из одной кодовой базы. Из неё же раздаётся словарь перевода для скрипта.

## Состояние

Версия 3.0 в разработке, готовых сборок пока нет. Последние выпуски в разделе [Releases](https://github.com/foulnike/AniMori-AniList-Toolkit/releases) (`v2.0.2` и раньше) — прежняя гибридная версия: она снята с поддержки и из рабочих веток удалена, но установленные копии продолжают работать.

Переезд на 3.0 произойдёт сам. Идентификатор программы (`com.foulnike.animori`), ключ подписи и адрес манифеста обновлений остались теми же, поэтому первый же тег `app-3.0.0` сдвинет `releases/latest`, и апдейтер внутри старой оболочки предложит обновиться. Настройки и токен лежат в том же профиле и подхватываются новой версией. Подробности — в [`docs/REPO-LAYOUT.md`](docs/REPO-LAYOUT.md).

Скриншоты появятся к первому релизу: снимки из README 2.x показывали сайт с юзерскриптом и новый интерфейс не описывают.

## Что уже есть

Шесть экранов: **Главная**, **Списки**, **Поиск**, **Тайтл**, **Студия**, **Настройки**. В меню четыре — на тайтл попадают из списков и поиска, на студию ведут чипы карточки.

- **Русский по умолчанию** — интерфейс написан по-русски; названия и описания подтягиваются с Shikimori или anime365 с указанием источника. Словарь перевода здесь не нужен: чужих страниц приложение не открывает.
- **Списки без ожидания** — коллекция AniList держится локальным снимком: открывается сразу и переживает обрыв связи. Где что лежит и когда обновляется — в [`docs/STORAGE-AND-SYNC.md`](docs/STORAGE-AND-SYNC.md).
- **Страница тайтла** — описание и названия по-русски, персонажи и персонал с русскими именами, студии — отдельным экраном.
- **Поиск по-русски** — по названиям тайтлов, а также по персонажам и персоналу.
- **Запросы мимо страницы** — к API обращается процесс программы, а не веб-часть: ограничения CORS её не касаются, заголовки под контролем.
- **Прокси** — оболочка применяет прокси из настроек к окну при запуске и умеет проверить адрес соединением; своей панели в интерфейсе пока нет.
- **Вход в AniList** — в отдельном окне; токен ложится в файл настроек программы и наружу не уходит.
- **Автообновление** — при запуске программа сверяется с последним релизом, проверяет цифровую подпись пакета, ставит обновление и перезапускается.
- **Оболочка** — внешние ссылки уходят в браузер по умолчанию, окно перезагружается кнопкой в шапке. Полный экран оболочка умеет, но кнопки для него в интерфейсе пока нет.

## Чего здесь нет

| Чего нет | Почему |
| :--- | :--- |
| Перевода интерфейса по словарю | у приложения свой интерфейс; `dictionary.json` остался юзерскрипту и раздаётся из ветки `main` |
| Плеера | прежний был скином вокруг кадра Kodik и жил в юзерскрипте; для приложения пишется свой, на прямых ссылках — [`docs/ARCHITECTURE-VIDEO.md`](docs/ARCHITECTURE-VIDEO.md) |
| Блокировщика рекламы | он имел смысл только внутри окна с чужим сайтом и уничтожен вместе с ним |
| Манги | снята из приложения; в юзерскрипте осталась |
| Юзерскрипта и режимов сборки | конфиг сборки теперь один и безусловный — [`docs/REPO-LAYOUT.md`](docs/REPO-LAYOUT.md) |

## Требования

Windows 10 или 11 и компонент **WebView2** — в Windows 11 и актуальной Windows 10 он уже установлен, иначе установщик предложит его загрузить.

## Сборка из исходников

Нужны Node.js и [окружение Rust и Tauri](https://tauri.app/start/prerequisites/).

```bash
npm install
npm run dev:app        # передний край в браузере
npm run tauri:dev      # окно приложения
npm run build:app      # передний край → dist/app
npm run tauri:build    # установщик → src-tauri/target/release/bundle/nsis/
npm run typecheck:all  # ядро отдельно, затем всё вместе
```

`npm run tauri:build` подписывает пакет обновления, поэтому ждёт переменные окружения `TAURI_SIGNING_PRIVATE_KEY` и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Свою пару ключей делает `npm run tauri signer generate`.

Исходники разложены по слоям: `src/shared/` — ядро (API, данные, кэш, мост), `src/app/` — экраны, компоненты и роутер, `src-tauri/` — оболочка на Rust. Ядро про оболочку не знает ничего: `npm run typecheck:shared` проверяет это отдельной сборкой, где каталога `src/app` не существует, и падает на любой стрелке из ядра в надстройку.

## Выпуск

Выпуск делает тег вида `app-3.0.0`: прогон на `windows-latest` сверяет номер в теге с `package.json`, компилирует Rust, собирает установщик, подписывает обновление и кладёт рядом `latest.json`. Описание релиза берётся из верхнего раздела `CHANGELOG.md`.

## Источники данных

| Источник | Назначение |
| :--- | :--- |
| `graphql.anilist.co` | данные и списки AniList |
| `shikimori.io`, `shikimori.rip` | русские названия, описания, персонажи, франшизы (`.rip` — запасное зеркало на случай недоступности основного домена) |
| `smotret-anime.online`, `anime365.ru` | тайтлы и описания (альтернативный источник/фоллбэк anime365) |
| `github.com` | манифест обновлений и подготовленные данные (`foulnike/animori-data`) |

Запросы идут из процесса программы. Ваши данные на сторонние серверы не отправляются: токен и настройки остаются на вашей машине, кэш — локальный. Как собираются подготовленные данные — в [`docs/DATA-PIPELINE.md`](docs/DATA-PIPELINE.md).
